# P10 v2 — Demo-focused cross-domain review

Derived from the verified training loop: the hub has saved/describe/deferred-plan entry paths; described sessions remain unsaved until reviewed; drafts autosave with revisions and retries; ghosts, timestamp rest timing, one-tap completion, transactional workout projection, and comparable summaries pass integration tests. Structured onboarding/profile context is durable and available to the training specialist. Five guarded 14-day ECP fixtures now provide labelled nutrition, training, sleep, activity, ordinary heart-rate, and check-in records.

## Objective

Polish only the proof-of-concept judging path. Do not expand the wireframe-deferred food catalogue or plan browser. Use one exact configured demo account to select an ECP, inspect its durable synthetic records, and run one live orchestrator review across Training, Nutrition, Sleep, and Recovery.

## Controls

- Keep `BRIO_DEMO_MODE` and exact demo email as the double guard.
- Never blend or relabel synthetic fixture rows as Apple Health.
- Make no model call while loading a profile; require the user to press Send.
- Use only server-derived ownership and consent-filtered tools.
- Keep exactly five possible actions: Progress, Maintain, Repeat, Reduce, Escalate.
- No diagnosis, praise, badge, recovery percentage, unsupported biomarker, automated plan commit, future scheduling claim, or unsupported helper sync claim.
- When Escalate applies, do not generate a prescribed session.

## Acceptance gate

1. Unit tests prove five deterministic profiles, fourteen complete days, labelled foods, stable owner-scoped identifiers, and coverage of the five actions as fixture intent.
2. API integration loads all five profiles and verifies 14 nutrition logs, 56 labelled foods, 14 check-ins, 84 synthetic health samples, four completed structured sessions, and five additional workouts per profile.
3. A repeat reset is idempotent and session completion still projects exactly once per session.
4. The live review calls Training, Nutrition, Sleep, and Recovery, discloses synthetic provenance at the start, reports observations and uncertainty, explains cross-domain interactions, and ends with one bounded editable action.
5. Static checks, contract/demo/training/ECP tests, and a clean production build pass.
6. Update coverage, decisions, state, test results, runbook, known gaps, and the agent-orchestration explanation from actual outcomes.
