# BRIO three-minute demo script

## 0:00–0:25 — Establish the product decision

Open `/`.

> “Brio is not another wellness dashboard and it is not primarily a chat app. It joins training, nutrition and recovery into one bounded, editable action. There are only five: Progress, Maintain, Repeat, Reduce and Escalate.”

Point to the example **Repeat** action, then the visible disagreement and policy reason. Point out **Synthetic inputs** and **Simulated decision** as separate labels.

> “This entire judged path is deterministic. It needs no model call and cannot present a simulation as live specialist execution.”

## 0:25–1:05 — Inspect the evidence

Choose **Explore the synthetic demo**. Keep the **Specialist disagreement** scenario selected.

> “These nine signals stay grouped as training, nutrition and recovery, but every tile is inspectable.”

Open one metric tile. Show source, input mode, observation time, evidence window, coverage, freshness and quality reason. Close it.

> “The comparison is against this synthetic person’s recent window. It is not a population threshold, diagnosis, readiness score or recovery percentage.”

Change the scenario to **Signal revoked**.

> “When sleep consent is revoked, Brio says ‘Not being read.’ It does not silently reuse the value. The current recommendation becomes stale.”

## 1:05–1:45 — Show the decision and user control

Return to **Specialist disagreement**. Scroll to the decision.

> “Readiness suggested Maintain. The prototype policy suggested Repeat. Brio keeps that disagreement visible and records why Repeat won. Uncertainty is on the same surface as the action.”

Select **Adjust**, choose another one of the five actions, enter a short reason, and record it.

> “An edit never overwrites the original recommendation. It creates a separate response event for audit.”

Reset the demo.

## 1:45–2:20 — Show durable product work

Use the rail to open **Training**.

> “The account product uses the same contracts. Training is a durable set ledger, not a screenshot: stable sets, warm-ups kept separate, load, reps, entered RPE, completion, rest timing and one idempotent workout projection.”

Open **Nutrition**.

> “Nutrition records only what the user enters. Intake stays separate from active energy; missing is not zero.”

Open **Recovery**.

> “Recovery shows qualitative evidence availability and ordinary heart-rate trend. There is no HRV claim or recovery percentage.”

## 2:20–2:50 — Prove governance and resilience

Open **Data** on an authenticated disposable account if available; otherwise use `/demo/data` and narrate the verified account route.

> “Every signal has its own default-off control. A change increments consent and invalidates current decisions. The user can inspect sources and the immutable recommendation audit, export JSON, or type DELETE to remove the account.”

Point to install guidance.

> “Brio installs as a PWA. Its service worker never caches APIs or authenticated health screens. Offline, it says account data needs a connection instead of showing stale records as current.”

## 2:50–3:00 — Close on truthfulness

> “The iPhone helper remains the Apple Health transport. It now checks server consent, scopes anchors to the signed-in account, reconciles deletions and advances only after acknowledgement. Physical device verification is still stated as a gap. Brio rules the data, never the athlete.”

Stop. Do not open the live-agent path during the reliable three-minute demo.
