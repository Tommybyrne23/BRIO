## P01 result envelope

**Objective.** Prove the baseline and protect existing work before changing application behavior.

**Patch identifier.** Working tree on `manus/brio-hackathon-20260912`; no application-source edits in P01. Documentation and evidence were added under `docs/manus/`.

**Verified baseline.** Both package lockfiles install with `npm ci`. Web and mobile lint pass. Mobile TypeScript passes. The initial standalone web TypeScript command fails because `LayoutProps` is generated by Next; after `next build` generates route types, the same command passes. The production build passes on Next.js 16.3.4. A local PostgreSQL 16 database was created and all existing Drizzle migrations applied through `npm run db:migrate`.

The public landing, sign-in, sign-up, and forgot-password pages return 200. Anonymous `/dashboard` redirects to `/sign-in`; anonymous `/api/health-samples` returns 401. Disposable local users can sign up and all three existing health-ingest payload shapes—single object, raw array, and `{samples}` wrapper—return 201 and are readable by the authenticated owner.

**Critical verified defect.** `health_samples.external_id` is globally unique. When account B posts an external ID already owned by account A, the route returns 201 but updates account A's row with account B's value and source. Account B then reads no row. This is a cross-account write-isolation bug. Workouts use the same global uniqueness pattern. P03 must change uniqueness and conflict targets to `(user_id, external_id)` and retain PostgreSQL null semantics.

**Authentication and route facts.** Better Auth supplies email/password, username, admin, Expo, and Next cookie plugins. Current sign-up has four visible fields; sign-in uses username/password. Social providers are not configured. Email verification is disabled. Password-reset URLs are logged server-side rather than delivered; this must not be described as sent email. Authoritative ownership and admin checks are in `db/auth-dal.ts`; `proxy.ts` is cookie-presence only.

**Agent and worker facts.** Authenticated `/api/chat` streams NDJSON and runs the real OpenAI Agents SDK. Current structured worker insights are not bounded product decisions. The worker is a separate restart-relative interval process, writes append-only insights, has no run ledger or consent gate, and defaults in code to `gpt-5-nano` while docs mention `gpt-5-mini`. Model and interval configuration are not fully forwarded/validated in Dokploy Compose.

**Mobile facts.** The Expo 57 helper reads steps, active energy, ordinary heart rate, and sleep in foreground/manual sync. It uses absolute custom API URLs and advances per-type anchors only after acknowledged uploads. Anchors are environment/type scoped but not user scoped; deletion events are ignored; auto-sync is not gated on a confirmed session or server consent. Native folders remain generated and disposable.

**Deployment assumption.** Preserve the existing Dokploy Docker Compose route with one-shot migrator, standalone Next runner, and separate worker. Docker is unavailable in this sandbox, so image/Compose verification is unverified. The sandbox public URL may be used for temporary browser testing, not as proof of the final Dokploy deployment.

**Secrets and environment.** A tracked-file and Git-history pattern scan found no exposed private keys or token-shaped secrets. `.env*` is ignored except `.env.example`. Environment names: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `OPENAI_API_KEY`, `OPENAI_AGENTS_MODEL`, `WORKER_INTERVAL_MINUTES`, and mobile-only `EXPO_PUBLIC_API_URL`. Secret values are excluded from docs and logs.

**Migrations.** Existing migrations applied successfully. No schema changes were made in P01.

**Data mode.** P01 used disposable local accounts and explicit test samples. No personal health records or model calls were used.

**Unverified external evidence.** Physical iPhone install, HealthKit authorization/sync, public HTTPS deployment, Dokploy service ordering, production auth cookies, and real model execution remain unverified.

**Next critical dependency.** Freeze shared serializable schemas and storage ownership before implementing migrations and handlers. The owner can perform iPhone provisioning in parallel, but mobile device evidence is not on the critical path because the deterministic labelled demo is mandatory.
